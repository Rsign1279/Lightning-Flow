# Troubleshooting

- **Shortcut already in use:** quit the older dictation instance or choose another action key under Shortcuts. Never run the developer console and desktop app with the same shortcut simultaneously.
- **No words in the target:** check History. A changed field, selection, focus excursion or input revokes insertion. Copy the retained transcript or carefully retry at the intended cursor. Do not retry blindly after a possibly partial paste.
- **Unsupported/password/read-only/elevated field:** use Copy from History. The app does not bypass Windows integrity levels or overwrite unreadable content. A working native/API bridge is required for a custom editor to offer verified delivery.
- **Clipboard restoration issue:** delivery and restoration are tracked separately; the notice tells you when a successful insertion left the transcript on the clipboard. A new user copy is preserved. Metafile/palette or overly large clipboard data uses direct Unicode before any paste.
- **Slow direct typing:** another application's global hooks can delay SendInput. The verified clipboard route avoids per-character keyboard events where the clipboard can be safely preserved. Native controls use targeted messages.
- **Missing runtime:** Privacy & settings → Repair GPU runtime. This can download dependencies with consent. Setup, workers and repair helpers run hidden.
- **CUDA/VRAM errors:** inspect Performance for actual provider/error. ASR never silently falls back to CPU. Other GPU applications are not stopped automatically. Select a smaller model or free GPU resources yourself.
- **Microphone errors:** choose a connected input in Microphone, run its unsaved test, then retry. Already captured speech is finalized and retained for review. The log offers Save retained audio and Retranscribe on GPU; retranscription updates the log without pasting. Privacy settings offer separate opt-in encrypted recovery across restarts. No partial recording is automatically uploaded.
- **Unexpected engine exit:** inspect Performance diagnostics and the Windows Application/System logs. Available desktop previews are retained as incomplete/provisional text. Restart the engine explicitly; unfinished audio in the terminated process may be lost. The original long-run abort was traced to a CUDA allocator cleanup exception after an NVIDIA reset. Version 0.6.1 isolates that native failure: export retained audio before restarting the engine; encrypted recovery survives only if it was already enabled and its save completed. See FIXES_0.6.1.md for verification and the remaining driver-reset uncertainty. There is no automatic CPU fallback or blind paste retry.
- **Locked recording:** press the shortcut again, or cancel with Ctrl+Alt+Esc. With Ctrl+Win selected, releasing either modifier ends a hold. The alternate Ctrl+Alt+key binding also ends on release. The overlay distinguishes locked, paused and processing states.

No application can guarantee failure-free insertion across every Windows app. Known limits and actual validation are in DESKTOP_VALIDATION.md.

For the protected original NVIDIA live report, use the narrow private exporter and see [KERNEL_DIAGNOSTICS.md](KERNEL_DIAGNOSTICS.md). Local analysis confirms an NVIDIA 0x117 timeout, but its underlying trigger remains unresolved. Current zero clock offsets do not disprove a past tuning state, and the WER `UserOC` label alone does not establish causation. Never upload a raw kernel memory report as a public GitHub issue.
