# NVIDIA kernel timeout investigation — November 16, 2026

**Symptom:** The original accelerated long-recording run coincided with a display-driver reset and a later native Python abort.

**Root cause:** The original WATCHDOG live kernel dump confirms a 0x117 NVIDIA timeout. The scheduler capture stack and driver pointer identify the failing display-driver path, not the submitting application or ultimate hardware/software trigger. The separate application dump identifies a subsequent CTranslate2 allocator cleanup exception. The initial timeout's trigger remains unresolved.

**Hypothesis tested:** WER's `Blackwell_UserOC` classification suggests investigating GPU tuning. Subsequent supported NVML queries return zero offsets, including all queried state identifiers 0–15 for graphics and memory. The local NVIDIA tuning database has no GPU-error/OC-result rows. These observations do not establish the incident's earlier tuning state and cannot confirm or eliminate tuning as a cause. The installed driver file passes Windows Authenticode verification, which does not establish runtime correctness. No speculative tuning/driver changes were applied.

**Changes:** Add a narrow Windows UAC export helper, data-only copy with SHA-256 verification, and private fixture tests. Resolve PowerShell through its absolute system location in the VBS launcher. Ignore raw memory/trace/event-report extensions. Publish the redacted findings in KERNEL_DIAGNOSTICS.md. The user's original helper error could not be recovered; do not claim its exact cause was identified. Direct elevated PowerShell export succeeded and the VBS syntax/path assembly passed a non-elevating check.

**Evidence:** The actual protected report was copied and verified locally. Signed Microsoft debugger components and matching public kernel symbols were used. `!analyze -v` returns `ANALYSIS_INCONCLUSIVE`; NVIDIA private symbols/internal context data are unavailable to this analysis. The secondary data block was enumerated without inventing an undocumented decoding. Original System errors in the incident window were NVIDIA events; absence of other recorded errors does not establish healthy hardware.

**Regression tests:** tests/test_kernel_export.py; the full 295-test suite passes. The source wheel builds using `uv build --wheel`. A pip build attempt was unavailable because this uv-managed environment has no pip module; no production dependencies were changed.

**Recording verification:** Fresh real-CUDA replay completed 100 hold and 100 hands-free cycles, one model initialization, 200 persistent log entries, no post-stop audio appends, and all five public example canonical/vocabulary checks. Median stop-to-result was 160.4/159.8 ms; p95 273.2/323.8 ms; maxima 760.7/517.5 ms. These are callback/replay timings, not physical global-hook or external-editor timings. Paired vocabulary processing used a public synthetic fixture, not the user's private bank or human speech.

Direct/isolated output matched on 32 actual CUDA decodes, with and without hints. Own-child termination in both modes retained audio/text and the control threads, with no automatic insertion or failed-worker reuse. A suspended owned child hit the bounded request deadline and was terminated; no display-driver reset was induced.

**Long-run verification:** Both 30-minute synthetic-audio cases passed with one model initialization, matching prior-release transcript hashes and unchanged synthetic WER (0.0415728). The final spoken marker was present, each case produced one result, all streams closed, raw audio was released and no audio appended after stop. Replay wall times were 323.2 s hold and 195.5 s hands-free; this is accelerated audio, not 30 minutes of physical recording. No NVIDIA TDR events occurred during either the long test or the full audit window. The event monitor also detects the original incident as a positive control. See the three fresh integration JSON reports and results/kernel-audit-2026-11-16.json. Source remains unchanged; this does not establish a driver fix.

**Related:** Version 0.6.1 already contains the native abort in an owned hidden CUDA interpreter. Its production source is byte-for-byte unchanged by this diagnostic commit. Models, decoding, precision, vocabulary behavior, input insertion and both shortcut modes were not modified. Kernel reports remain private and ignored; no raw dump/trace is sent to GitHub.

**Status:** BLOCKED for the original driver-reset trigger: the available report is inconclusive. No verified driver fix is claimed. Application native-failure containment is independently verified. Further causal evidence would require vendor interpretation of the private NVIDIA data or a reproducible fault with pre-fault tracing, not an unsupported driver/settings change.
